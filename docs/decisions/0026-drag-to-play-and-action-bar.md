# 0026 · 拖拽出牌、操作栏上移、胡牌按需出现

状态：`Accepted`（实现完成）
日期：2026-07-29

## 背景

真人试玩后的三条反馈：

1. 出牌希望能拖拽，不只是「点选 + 按按钮」。
2. 出牌 / 亮牌 / 胡牌按钮放在手牌**上方**更合适（原来在手牌下面）。
3. 胡牌按钮平时不要显示，只有真的能胡时才出现。

## 决定

### 1. 操作栏移到手牌上方

`index.html` 里 `#actionRow` 挪到 `#handZone` 之前。

这不只是换个位置，还顺手让拖拽变得自然：**拖着牌往上走，第一个碰到的就是按钮**。
按钮同时是落点，不需要额外发明一套拖拽目标。

DOM 顺序上 `#actionRow` 在 `#handZone` 之前，所以手牌天然画在按钮上层
（`#handZone` 加 `position:relative; z-index:5`），拖起来的牌能盖过按钮往上走。

### 2. 胡牌按钮按需出现

`huButton.hidden = !state.canHu`。按钮**出现本身就是提示**，不需要额外的文案。
出现时仍带 `.ready` 的呼吸高亮。

配套：求签结束后的焦点回退原来只跳过 `disabled`，现在也跳过 `hidden`，
否则焦点会落到一个看不见的按钮上。

### 3. 拖拽出牌

- 按住手牌移动超过 **8px** 才算拖拽，否则仍然是普通点选。
- 拖一张**没选中**的牌 = 清空选择只出这一张；拖一张**已选中**的牌 = 出整组选择。
  「拖 = 出我手上拿着的东西」，可预期。
- 落点三种：
  - 落在**可用按钮**上 → 执行那个按钮的动作。
  - 落在**牌桌**上 → 执行默认动作（能亮组就亮组，否则换牌）。
  - 落在**其他任何地方**（包括放回手牌）→ 什么都不做。
- 拖拽中牌桌中央有 `#dropHint` 明确写出「松手：亮刻子」这类结果；没有合法落点时
  显示灰色的「松手不会出牌」。可用按钮加虚线描边，指针下的那个变实线 + 高亮。
- 弹簧新增 `x` 通道（刚度 420 / 阻尼 26，比其它通道紧），牌跟着指针走并按水平位移轻微倾斜。

## 三个踩到的坑

这三个都是实测才暴露的，值得记下来：

1. **拖拽期间绝对不能重建手牌。** 拖起一张未选中的牌会改选择 → `emit` → `renderAll` →
   `renderHand` 把正在被拖的那个节点换掉，拖拽当场断掉。
   `renderHand` 现在在 `dragging.active` 时只更新 `.sel` 类，不重建 DOM。

2. **正在被拖的牌必须 `pointer-events:none`。** 它盖在按钮上方，
   不设的话 `document.elementFromPoint` 永远只命中这张牌，一个落点都找不到。
   指针捕获不走命中测试，所以事件照旧送到这张牌上。

3. **落点在拖拽过程中不能移动。** 第一版 `#actionHint` 的文案会随拖拽状态变长变短，
   `#actionRow` 是 `flex-wrap:wrap`，一换行按钮就从指针底下跑掉——
   实测表现是「拖到禁用的亮组上却触发了换牌」。
   修法是结构性的：`#actionRow .btn{min-width:118px}`（文案从「换牌」变「换掉 3 张」也不撑宽），
   `#actionHint{flex:0 0 100%}`（提示单独占一行，长度永不影响按钮位置）。

另外补了一条兜底：`setPointerCapture` 失败时 `pointerup` 不会落在那张牌上，
没有 window 级的 `pointerup / pointercancel / blur` 兜底，`dragging` 会永远挂着，
之后再也拖不动。兜底必须走**冒泡**阶段——捕获阶段会抢在牌自己的 `pointerup` 之前，
把正常的落点吃掉。

## 影响与验收

- 规则、数值、存档 schema 未动。`node --test tests/*.test.mjs` 137 项全绿。
- `node tests/src-viewport-smoke.mjs` 45 项全绿：无裁切、无遮挡、无页面滚动，最小可点 ≥44×48px。
- 浏览器实测四种落点：可用按钮（执行）、禁用按钮（作废）、牌桌（默认动作）、手牌内（作废），
  以及拖拽后 `dragging` 不残留。
- `.tile` 加 `touch-action:none`，触屏拖拽不会被浏览器的滚动手势抢走。

## 后续已解决的问题

窗口宽度约 850–900px 时 14 张手牌会换到第二行：`refreshScale()` 给每张牌算的宽度预算
（`(width-8)/14 - 3`）比 `.tile{min-width:44px}` 加 3px 间距的实际下限小，
14 张需要 655px 而手牌区只有 638px。两侧标准视口（1280 / 844×390）都放得下，
所以当时自动 smoke 没覆盖到这个中间宽度。`0027` 的全宽底栏被真机审美试玩否决；
替代的 `0028` 新增 667×375 回归，只在窄横屏缩短左栏并让手牌轻微叠边。
