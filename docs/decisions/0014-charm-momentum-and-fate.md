# 0014 — 灵签双价值：助势与改命

状态：`Proposed`

日期：2026-07-26

实现：改命玩法尚未实现。本记录只确定下一版动态改牌实验的目标、边界和首批内容；当前 `src/` 已先实现 `0015` 的签阶、待缘与奇缘框架，但没有借张、移花、归一或听风。

纸面与现有界面复核：`docs/playtests/2026-07-26-charm-fate-paper-review.md`。

后续提案：`0015-charm-tiers-and-pending-omens.md` 为灵签增加银 / 金 / 彩签阶，并允许奇缘留下一个跨副保留、下次求签时消耗的签兆。该扩展仍为 `Proposed`。

## 与现有提案的关系

`0009` 和 `0010` 把灵签定义成“亮一组后，以一个开运位换一次本副三选一”；`0011` 又把灵签与番谱、福将、牌骨、牌印分开。本记录不增加第六类内容，也不改变灵签只持续 `本副` 的边界，而是扩展灵签的职责：除了提高本副收益，还能临时调整当前手牌结构。

如果本提案进入实现，它会修订 `0009` 的固定三位置 `本组签 / 牌型签 / 奇签`，以及 `0011` 中“灵签只加牌值、番势或少量金币”的限制。以上记录继续保留为历史实验依据。

## 要解决的问题

当前灵签只有在玩家已经接近胡牌、愿意用长期金币换本副分数时才明显有吸引力。玩家还没有胡时，单纯的 `+牌值` 或 `+番势` 没有解决眼前最重要的麻将问题；玩家已经能胡时，现有灵签又很少改变“现在胡，还是追更大的胡”这个决定。

下一版要让玩家在亮组后看见三条真正不同的选择：

```text
助势：不动牌，立刻提高本副得分
改命：动当前牌，让这副更容易成胡，或者从小胡升级成大胡
奇缘：根据局面再给一张高波动、牌型或少量返金选项
```

灵签存在的主要理由应当是前两条。财签可以保留为低频保本选项，但不能再独自承担第三个固定位置的价值。

## 核心术语

| 术语 | 含义 | UI 标签 |
|---|---|---|
| 助势签 | 不改变手牌身份，只增加本副牌值、番势或条件得分 | `加分` |
| 改命签 | 临时改变当前手牌或牌墙交互，只持续本副 | `成胡` 或 `升胡` |
| 成胡 | 效果使“还差 N 张”减少；若从 1 变 0，则当场进入可胡状态 | `还差 1→0` |
| 升胡 | 效果保持当前仍可胡，并新增七对、碰碰胡、清一色、一条龙、大三元或大四喜等已支持番种 | `新增 清一色` |
| 奇缘位 | 三选一的第三个展示职责，可出现另一张助势签、适配牌型的签或低频财签 | 依实际效果 |

`助势` 和 `改命` 是灵签内部的两条价值线，不是新的商店系统。卡面必须直接写结果，不能只写抽象的“提高运势”。

## 三签选一的新结构

每次亮组后仍然出现三张灵签，但固定职责改为：

1. **助势位**：至少一张与刚亮组合或当前番种有关的稳定加分签。
2. **改命位**：尚未使用本副改命机会、且当前确实存在合法有效目标时，给一张动态生成的改命签。
3. **奇缘位**：从牌型助势、高波动效果或少量返金中抽取一张。

如果当前没有任何合法且有收益的改命目标，改命位自动回退为一张适配当前牌面的助势签；绝不展示选了也无法生效的死签。三张仍不能完全相同，顺序和内容仍由可记录 seed 决定。

第一版建议每副最多真正使用 **1 张改命签**。在玩家取得改命签之前，后续亮组仍可再次遇到合法的改命选项；一旦使用，本副之后的改命位全部回退为助势或牌型签。这样玩家需要决定“现在救牌，还是把唯一改命机会留给更大的胡”，又不会连续六次改牌把麻将求解完全抹掉。

## 首批改命签

第一轮只测试四种清楚、单向、可预览的效果：

| 名称 | 稀有度建议 | 用途 | 规则草案 |
|---|---|---|---|
| 借张签 | 常见 | 成胡 | 选择 1 张未亮牌，查看牌墙前 3 张，从中选 1 张交换；只有至少一种交换能减少“还差几张”时才出现。 |
| 移花签 | 常见 | 成胡 / 升胡 | 选择 1 张未亮数字牌，把它临时改成同点数的另一门花色，例如五万改成五条；只显示能减少距离，或能在保持可胡时新增番种的目标。 |
| 归一签 | 进阶 | 升胡 | 选择 1 个已亮的数字牌组合，把整组临时改成另一门花色，点数不变；只在仍为合法组合并能立即新增清一色或一条龙等番种时出现。 |
| 听风签 | 稀有 | 成胡 | 仅在“还差 1 张”且牌墙中存在实际成胡牌时出现；选择 1 张未亮牌，再从合法完成牌中取 1 张交换，使当前结构当场可胡。 |

`听风签` 是保底型高强度效果，不应成为每次改命位的常见结果。第一版先验证“动态合法目标”和“成胡 / 升胡预览”，暂不加入万能牌、字牌变数字牌、任意改点数、复制整组或直接宣告任意胡牌。

## 改命的合法性边界

每张改命签在进入三选一前先枚举所有可执行结果。一个结果必须同时满足：

- 14 张结构牌数量不变；杠仍按现有结构数量规则计算。
- 同一有效牌种最多 4 张，不能凭空造出第五张同名牌。
- 单张移花只作用于未亮牌；不能把一个已锁定顺子里的单张改掉并破坏组合。
- 已亮组只能被明确写着“整组改花色”的效果改变，改变后仍须是同类合法组合。
- 第一版不改变字牌的花色或点数，也不把数字牌变成字牌。
- `成胡` 目标必须让“还差 N 张”严格减少。
- `升胡` 目标必须保持当前仍可胡，并立即新增至少一个已支持的记名番种；只提高理论潜力但没有可见结果的目标首版不展示。

目标列表只展示满足以上条件的牌。若一个签没有目标，它就不能进入本次三选一。

## 与金币和换牌次数的关系

当前实验参数同时存在：

- 每个未用开运位：`+12 牌值 +2 金`。
- 每次未用换牌：`+2 金`。

因此首版改命签建议 **不消耗普通换牌次数**，但每副限用一次，并且必须先亮组花掉一个开运位。它的经济并非免费：

| 做法 | 开运位变化 | 换牌变化 | 相对金币结果 |
|---|---:|---:|---:|
| 不亮组，正常花 1 次换牌成胡 | 保留 `+2 金` | 少一份 `+2 金` | 两项抵消 |
| 亮组，取得 1 张改命签成胡 | 少一格 `-2 金` | 保留一份 `+2 金` | 两项抵消 |
| 已经能胡，亮组用改命签升胡 | 少一格 `-2 金` | 无需省下一次本来要用的换牌 | 为大胡支付 2 金机会成本 |

这让改命成为“用开运位替代一次普通换牌，换取确定性或牌型升级”，而不是额外再收一次换牌造成双重惩罚。若实测改命成为必选，再测试 `消耗 1 次换牌`、降低出现率或缩小效果，不能在第一版同时改三项。

通过借张签或听风签发生的交换属于 `改命` 事件，不属于普通 `换出` 事件：

- 不减少 `swapsRemaining`。
- 不触发回风印等“换出时”牌印，也不能因此返还换牌。
- 被换走的实体牌进入弃牌区；从牌墙取得的实体牌按确定顺序移出牌墙。

卡面详情必须写明“本次不耗换牌，也不触发换牌牌印”，避免玩家把两套事件混为一谈。

## 与牌骨、牌印和实体牌的关系

临时改花色需要把两个概念分开：

```text
本体牌种：这块实体牌原来是什么；决定它携带哪种牌骨和牌印
有效牌种：这副牌当前按什么花色点数参与胡牌、番种与画面显示
```

- 移花或归一只改变 `有效牌种`，本副结束后消失。
- 胡牌分解、番种识别和同名最多四张检查使用有效牌种。
- 牌骨、牌印仍跟随本体牌种，不会因为五万临时变成五条就偷取五条的牌骨或牌印。
- UI 在改变后的牌角显示小型 `万→条` 标记；详情同时显示本体和当前有效牌种。
- 借张或听风是实际交换实体牌，新取得的牌自然携带它本体牌种对应的牌骨和牌印。

当前 `Tile` 只有 `{ id, suit, rank }`，规则、渲染和牌种改造都直接读取同一字段。未来实现前必须加入独立的本副有效牌种覆盖层，不能直接覆写实体牌的 `suit / rank`，否则牌骨、牌印、存档和复盘会产生歧义。

## 交互时序

```text
亮出合法组合
→ 三张灵签原位展开，并显示 加分 / 成胡 / 升胡 / 返金 标签
→ 选择改命签
→ 只高亮合法目标；点击目标显示改变前后预览
→ 显示“还差 2→1”或“普通胡→普通胡·清一色”
→ 确认后一次提交，返回牌桌；取消则回到原三签
```

- 不使用拖拽、长按或悬停；选签、选目标和确认都支持触控与鼠标。
- 借张签的牌墙候选与手牌目标分成两步点击；移花签点击手牌后，再点最多两个合法花色按钮。
- 横屏在牌桌中央原位展开候选；竖屏使用底部全宽面板，手牌仍留在上方可见，不弹出多层对话框。
- 所有目标点击区以 48×48 CSS px 为目标；状态在旋转、后台恢复和读档后不能丢失。
- 普通三选一平均仍以 5 秒为目标；包含目标选择的改命流程首轮以 8 秒内完成为目标。

## Seed 与存档要求

- 三签内容、牌墙候选和合法目标必须由当前手内状态与 seed 唯一决定。
- 选中改命签但尚未确认目标时，存档要记录所选签、候选目标和预览状态；重载不得重新抽签或更换牌墙候选。
- `问签印` 可以重抽三张签，但重抽前后都只能从当时合法的改命结果中选择；重抽不能改变手牌或消耗唯一改命机会。
- 手气 `签气` 当前会在开局自动送一张被动灵签。第一版不得自动抽中需要选目标的改命签；要么只从助势池取得，要么以后改成显式三选一，不能静默替玩家改牌。
- 当前 schema v4 已能保存签阶、签实例和签局，但还没有临时有效牌种与改命选目标中间态；实现本提案时继续扩展 v4 字段，并把所有旧牌迁移为“无临时覆盖”。

## 最小实现与测试顺序

1. 先实现独立的有效牌种覆盖层与已亮组合法性校验，不接 UI。
2. 只接 `移花签`，验证未亮数字牌在成胡和升胡两种情形中的规则、预览与存档。
3. 再接 `借张签`，验证固定牌墙三选一、实体牌守恒和经济。
4. 稳定后接 `归一签`，验证已经能胡时从普通胡升级到清一色或一条龙。
5. 最后接稀有 `听风签`，验证保底强度和出现率。
6. 固定 seed 覆盖：有合法改命、无合法改命、已经可胡、七对、已亮组、同名四张上限、牌骨 / 牌印、问签印重抽、存档恢复。
7. 在 `config/viewports.json` 全部 required 视口完成触控流程，再进行真人试玩。

## 主要风险

1. **改命成为必选**：如果它稳定省一次换牌又能升番，玩家会无脑亮第一组。先用每副一次、动态出现条件和无直接加分控制强度。
2. **麻将求解被自动答案取代**：界面只展示合法目标，不直接自动选择“最高分答案”；强制成胡只留给稀有听风签。
3. **六次三选一更慢**：目标选择比被动加分多一步，因此每副只允许一次，并采用原位高亮与一步预览。
4. **牌种身份混乱**：若本体牌种和有效牌种没有分别显示，玩家会不懂牌骨、牌印跟谁走。
5. **经济被暗中抬高**：改命保留未用换牌的金币，必须和失去的开运位金币一起模拟，不能只看卡面分数。
6. **动态卡牌变成死选项**：改命签必须先算出至少一个有效目标才可出现，不能选择后才提示“无法使用”。

## 成功信号

- 新玩家能复述：“加分签让这副更值钱，改命签会真的动我的牌。”
- 未胡时，玩家会在至少一种固定牌谱里选择改命来减少距离；已胡时，会在至少一种牌谱里用改命追清一色或一条龙。
- 所有出现的改命签都有至少一个合法目标，预览结果与提交结果完全一致。
- 同一 seed 与同一存档状态始终产生相同三签、目标和牌墙变化。
- 改命后不会出现第五张同名牌、非法已亮组、结构数量错误或牌骨 / 牌印错绑。
- 普通三选一平均不超过 5 秒，带目标的改命流程平均不超过 8 秒。
- 在固定牌谱中，直接胡、选助势冲分、选改命求稳 / 升胡至少各有一次合理场景，没有一个选项在所有局面通吃。

## 接受或回退条件

本提案只有在规则测试、required 视口检查和真人试玩都通过后才能提升为 `Accepted`。

- 若玩家总选改命：降低出现率、限制只能成胡或只能升胡，或让它消耗换牌；一次只改一个变量。
- 若玩家看不懂本体 / 有效牌种：先退回只做实体交换的借张签和听风签，不做临时改花色。
- 若目标选择让单次抽签明显超过 8 秒：减少候选数量，或把复杂升胡签移到较低频稀有池。
- 若改命仍不能与金币路线形成取舍：重新标定开运位与未用换牌金币，不用单纯提高灵签数值掩盖问题。
