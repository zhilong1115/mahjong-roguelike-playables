# 0027 · 横屏全宽手牌与紧凑状态分组

状态：`Rejected`（2026-07-31 真机试玩否决：顶部构筑带破坏原有层级，牌桌也被过度压缩）

日期：2026-07-31

## 试玩结论

这版确实让 667×375 的 14 张手牌保持单排，但代价太大：本局构筑被压成牌桌上方的一排小字，
左侧原本清楚的状态 / 构筑层级被打散，开运位与牌桌的可用高度也明显减少。用户真机结论是
“布局还不如之前的”。因此本记录保留为失败实验，不再作为现行布局依据；替代方案见 `0028`。

## 要解决的问题

当前横屏把左侧状态栏从顶部一直铺到底部，手牌只能使用右侧主区的剩余宽度。844×390 自动矩阵刚好能放下，
但较窄的真实手机横屏会把第 14 张牌挤到第二行。继续缩小麻将牌会直接损害本游戏最重要的识牌和触控体验。

同时，侧栏把所有状态平铺成四组数字，其中两项已经在别处完整表达：

- `还差几张` 与操作提示、可胡按钮重复。
- `空位数量 / 预计金币` 与六个开运位里的空位和 `+金币` 重复。

成功信号：667×375 与 844×390 横屏都稳定显示 14 张单排手牌；侧栏只保留需要持续查看且没有别处替代的信息；
玩家仍能一眼区分关卡进度、当前牌势、本副资源、本局构筑四组状态。

## 决定

### 1. 手牌区脱离右侧主区，横跨整个底部

- 将操作栏和 `#handZone` 放进独立的 `#handDock`，作为 `#app` 的底部整行。
- 横屏上方仍是左侧状态栏与右侧牌桌；左栏在手牌上方结束，不再占用手牌宽度。
- `refreshScale()` 按手牌区真实宽度计算牌面，而不是按右侧牌桌宽度估算。
- 横屏 667px 以上必须保持 14 张单排；不使用横向滚动，也不以缩成难辨的小牌作为解法。

### 2. 本局构筑从左栏移到牌桌上方的横向构筑带

- 左栏只承担关卡、牌势和本副资源；福将、番谱、牌骨、牌印、牌帖统一属于“本局构筑”。
- 构筑带与牌桌同宽：福将保持有限将位可见，番谱 / 牌骨 / 牌印 / 牌帖继续使用可点摘要打开明细。
- 玩法、百牌谱、重开属于辅助操作，固定在横向带右端的独立 `nav` 中，不混入福将或改造摘要。

### 3. 侧栏状态去重并重新分组

| 分组 | 常驻内容 | 处理 |
|---|---|---|
| 关卡进度 | 圈 / 关 / 目标 / 已得分 / 待结算金币 | 保留 |
| 当前牌势 | 牌型、牌值 × 番势、当前预估总分 | 保留 |
| 本副资源 | 剩余换牌、已入账金币、待缘位 | 保留 |
| 本局构筑 | 福将、番谱、牌骨、牌印、牌帖 | 移到横向构筑带 |
| 成胡距离 | 还差几张 / 可胡 | 从侧栏删除，由操作提示和按需出现的胡牌按钮表达 |
| 空位收益 | 空位数 / 预计金币 | 从侧栏删除，由六个开运位直接表达 |

待结算金币不与已入账金币合并：一个会在过关后入账，一个可立即消费，含义不同。

### 4. 压缩开运区与操作区，但不压缩触控目标

- 矮横屏开运牌架从上一轮的 82–88px 收到约 66–72px；签图、签名和签阶仍同时存在。
- 操作按钮只占一条最小 44px 高的操作带；提示在矮横屏继续隐藏，避免重复说明。
- 手牌、主要按钮和待缘位的触控目标仍以 44–48px 为底线。

## 没有采用的方案

- **只缩小牌**：能暂时塞下，但会破坏识牌和触控，是把结构问题转嫁给核心交互。
- **手牌横向滚动**：玩家无法同时比较 14 张牌，也不符合横屏基准。
- **彻底隐藏状态栏**：目标、牌势和资源会失去持续反馈；本轮改为去重与分组，而不是清空信息。
- **把14张牌重叠成扇形**：会改变点击命中与排序阅读，先用全宽底栏解决。

## 影响与验收

- 只改 DOM 分组、CSS 响应式布局与显示字段，不改规则、数值、随机、存档 schema 或 Library。
- required 六视口继续无页面滚动、关键裁切、操作遮挡或状态重置。
- 新增 667×375 紧凑手机横屏回归：14 张牌必须一排、每张点击区至少 44px、手牌区宽于右侧牌桌区。
- 844×390 同屏仍能看见六个开运位、牌桌、操作按钮和完整手牌；亮一组后的代表牌与签面不能被挤掉。
- 若真机认为构筑带过密，下一步优先把空将位收成一个明确的 `0/4` 容量标，而不是重新挤占手牌宽度。
