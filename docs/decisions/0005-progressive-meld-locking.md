# 0005 — Progressive Meld Locking

状态：`Proposed`

日期：2026-07-25

## 首轮试玩反馈

用户试玩后指出，强制把四个面子和一个将全部手动锁定，实际上把“四面一将”写死成唯一流程，无法自然支持七对；同时它把胡牌资格与主动打出组合赚取收益混为一件事。

因此本提案暂不升级为 `Accepted`，当前 Demo 只作为 V1 对照。后续优先验证“完整结构可随时胡、亮组用于赚分和触发构筑”的 V2 Idea，见 `0007-hu-eligibility-and-reveal-scoring.md`。

## 要解决的问题

如果每次把对子、顺子或刻子打掉并补回 14 张，玩家正在形成的麻将结构会被破坏，完整胡牌只能依靠偶然摸成。需要一个既保留“点击组合”的即时反馈、又让每一步都推进最终胡牌的核心循环。

## 提案

把桌面分为两个区域：

- **未整理区**：仍可用于换牌或组成组合的牌。
- **组合区**：已经锁定的对子、顺子、刻子和杠。

两区中的牌都属于玩家。普通胡以四组面子和一对将为目标；当两区共同形成合法结构时触发胡牌结算。

流程：

```text
14 张未整理牌
→ 单张换牌，或锁定一个有效组合
→ 未整理牌逐渐减少，组合区逐渐完成
→ 四面子一将
→ 胡牌结算
```

锁定 2–3 张时不补牌，因为这些牌仍由玩家持有。杠的第四张作为附加牌，不占用十四张结构槽位，并摸一张补张牌。

当前 Demo 要求四个面子与一个将牌都由玩家明确锁定归位后，“胡”按钮才可用。系统可以提示当前全部牌已经存在合法解，但不会自动把未整理牌变成最终组合；这是为了防止玩家跳过锁组，从而让本次试玩真正验证渐进组牌。

## 玩家价值

- 每一步都能看见牌面从杂乱变成完整胡牌。
- “现在锁定稳定组合”与“继续等待高价值胡法”形成风险选择。
- 操作规则短：一张换，成组留，凑齐胡。
- 与只选择牌型重复计分的扑克式循环形成清晰差异。

## 与肉鸽系统的接口

福神牌和遗物可以监听明确事件：

- `onSwap`：换牌时。
- `onGroupLocked`：锁定对子、顺子或刻子时。
- `onGroupUpgraded`：对子升级刻子等。
- `onKong`：形成杠并补张时。
- `onHu`：完成任意胡牌时。
- `onHuPattern`：完成清一色、大三元等特定胡法时。

Boss 也可以围绕这些事件修改规则，例如提高某类组合价值、限制某个槽位或改变换牌预算。正式代码仍通过规则事件和平台适配接口分离。

## 主要风险

- 过早锁定可能让牌局在玩家不知情时变成无解。
- 后半段未整理牌太少，可能只剩机械换牌。
- 玩家可能误以为锁定组合已经“打出去”、不属于胡牌。
- 七对、十三幺等特殊结构不能直接套用四面子一将的槽位。
- 杠导致实体牌数超过 14，需要清楚区分结构槽位与附加牌。

## 待决定

1. 锁定组合是否可拆。当前推荐：确认前免费撤销；进行下一次摸牌后锁定，特殊效果才可拆组。
2. 是否允许先锁定多个对子，之后选择其中一个作为将。
3. 牌局的单张换牌预算和流局条件。
4. 胡牌自动触发还是主动宣告。
5. 特殊结构使用独立模式、临时槽位，还是延迟锁定。
6. 锁组只累积待结算筹码，还是也造成少量即时伤害。

## 最小测试

先做无美术、固定 seed 的规则原型，不接商店和平台 SDK。每组测试记录：

- 第一次有效操作所需时间。
- 每次可理解的合法选择数量。
- 完成胡牌所需换牌数。
- 想拆组或误锁的次数。
- 无解、流局和胡牌比例。
- 最后一到两张是否出现长时间机械等待。

## 成功信号

- 新玩家在 45 秒内能复述“一张换、成组留、凑齐胡”。
- 玩家能指出锁定组合仍属于自己的 14 张结构手牌。
- 单次选择通常在 5–15 秒内完成。
- 胡牌主要来自连续决策，而不是起手或最后一摸的纯运气。
- 锁组过程中持续有可见进度和期待感。
