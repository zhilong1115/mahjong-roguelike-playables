# 0025 · 古典水墨视觉统一与大开运位

状态：`Accepted`（用户明确选择古典水墨方向；首轮实现后等待手机审美试玩）

日期：2026-07-29

## 要解决的问题

`0024` 已经证明独立卡图、单牌亮组和更厚实的麻将牌能提高完成度，但牌桌仍保留蓝灰街机机台、
深绿电子绒布和像素牌匾三套语言，生成式卡图、Canvas 麻将牌与主界面并不像同一个世界。
开运位虽然比旧版更高，仍然只是顶部细栏，和它在玩法中“本副构筑核心”的重要性不匹配。

成功信号：不看文案也能把整个游戏认成同一套“宣纸、墨、朱砂、旧木、温玉”世界；
横屏第一眼先看到开运签与牌桌，而不是蓝色状态机；六个开运位花掉后仍能读清签图、签名和签阶。

## 决定

### 1. 统一材质语言

- 主色改为宣纸米白、松烟墨黑、旧木褐、温玉青与朱砂红；金色只做奖励和签阶强调。
- 面板从蓝灰塑料机台改成压边宣纸 / 木框；按钮仍保持高对比和明确按压反馈，不牺牲可读性追求“仿古”。
- 保留 WebGL 缓慢流动，但色彩改成淡墨晕染；关闭动画或 WebGL 不可用时仍显示同一水墨底图。
- 系统正文继续使用本机可用的清晰中文字体；楷书 / 宋体只用于 Logo、标题与大字标，不从网络加载字体。

### 2. 牌局与标题页使用两张原创水墨背景

- 牌局背景是低对比的横幅：宣纸纤维、远山、雾、水痕与少量朱砂印，中央必须留足负空间给亮组和牌。
- 标题页背景可以更有戏剧性：山水、云雾、月与牌桌意象，但不直接生成文字或 Logo。
- 两张图都保存为本地 WebP，不能产生外部请求；Logo 与按钮由代码单独叠加，避免生成图片里的中文错误。

### 3. 麻将牌与牌背改为“纸本拓印 + 玉石牌坯”

- 牌身仍由确定性 Canvas 绘制和缓存，保持 34 个牌种清晰、牌骨 / 牌印兼容与零网络请求。
- 牌面从亮瓷电子感改成温润旧象牙 / 宣纸釉面：墨色刻字、朱砂万字、石绿筒条、淡墨毛边。
- 牌背从景泰蓝双框改为乌木 / 旧漆底上的水墨纹样：山、云、回纹、北斗，各牌组仍可辨认。
- 不把生成式山水直接塞进每张小牌；小尺寸规则物件优先用代码保持轮廓和对比。

### 4. Logo 改为独立书画印记

- Logo 保留工作名 `天胡 / TIANHU`，但从像素牌匾改成“墨圈 + 两字行楷 + 朱砂方印 + 小号英文”的代码绘制标记。
- 中文是视觉主体；英文只是产品识别辅助。Logo 必须在 360px 宽手机和标题页大图上都保持清楚。

### 5. 开运位成为牌桌的主要构筑区

- 横屏六格仍一排，但高度提高到约牌桌可用高度的 22%–28%，主动挤占牌桌空间；已取得灵签显示更大的插画。
- 桌面横屏整条牌架目标高度约 126–132px，844×390 矮横屏约 82–88px；竖屏仍为 3×2，但每格不能低于 54px。
- 牌桌中央亮组已经压成单张代表牌，因此优先把新增空间给开运位；不能通过缩小 14 张手牌或主要按钮换空间。
- 空位仍显示 `+金币` 和编号，花掉后用图案、签名、签阶与组合类型说明价值，颜色不是唯一信息。

## 资产与原创边界

- 水墨背景由 OpenAI 图像生成工具为本项目全新生成，不含第三方角色、Logo、字体或可识别游戏构图。
- 牌、牌背、Logo 与 UI 框架为项目代码原生绘制，不复制第三方麻将素材或《小丑牌》的牌桌 / CRT 外观。
- 现有灵签与福将 Library id、规则、存档和图谱映射保持不变；这一轮只改变视觉与布局。

## 验收与回退

- `config/viewports.json` 六个 required 视口无页面滚动、关键裁切、手牌溢出或不可点按钮。
- 844×390 能同时看见六个放大开运位、最多四个单牌亮组、14 张手牌、牌墙预览和主要操作。
- 360×800 能完成所有操作；若大开运位挤掉中央亮组，优先压缩次要 HUD 文案，不缩小主要触控区。
- 背景图合计体积先控制在 900 KB 内；若低端设备解码或首帧明显变慢，降低 WebP 尺寸 / 品质而不回退视觉方向。
- 真人若认为“太灰、看不清”，先提高牌与按钮局部对比，不整体退回蓝灰街机配色。
