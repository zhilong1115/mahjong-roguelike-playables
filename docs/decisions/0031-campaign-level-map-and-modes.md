# 0031 · 关卡地图、星级目标与自由模式

状态：`Idea`（用户提出外层方向，尚未决定关卡数量、星级规则或解锁结构）

日期：2026-08-01

## 玩家问题

当前标题页直接进入一整局，东 / 南 / 西圈只表现成 Run 内部的进度。即使牌桌系统已经丰富，
外层仍像“打开一个规则 Demo”，不像一般小游戏那样让玩家看到关卡、目标、完成度与下一步。

目标不是简单再画一个菜单，而是给玩家三种清楚的期待：

1. 我现在打到哪一关，下一关有什么特色。
2. 这一关过了，但还能不能用更好的表现拿到更多星。
3. 我不想推进时，能不能进入不受关卡目标约束的自由模式。

## 候选结构

```text
标题页
→ 闯关模式：关卡地图 / 章节
   → 一个章节暂以四圈为概念单位
   → 每圈有自己的规则、视觉和目标
   → 章节末进入独立 Boss 关
   → 每关按清楚的附加目标评 1–3 星
→ 自由模式：使用已解锁内容，自选牌组 / seed / 规则打一局
→ 百牌谱 / 教学 / 设置
```

“四圈 + Boss”目前只是表达章节节奏的候选，不直接替换 `0017` 现有东南两圈六关切片。
关卡特色应该优先来自一条可预告规则、目标牌型、牌墙或构筑条件，而不是每关新增一整套隐藏规则。

## 星级原则候选

- 1 星只检查过关，不能让没拿满星等同失败。
- 2 / 3 星来自可提前看见的挑战，例如达到更高分、保留更多签缘、完成指定番种或限制使用锦囊。
- 同一关最多同时追一个附加轴，避免玩家在 14 张牌、构筑和多个隐藏任务之间来回读说明。
- 星星优先承担展示、解锁新关或新内容池，不直接提供永久数值碾压。

## 为什么暂不实现完整地图

- 现有 `0017` 的局长、商店密度和目标分仍未真人验证，直接批量做关会把实验参数固化成内容成本。
- 需要先决定“关”是一副牌、一个圈、还是一段包含商店的短 Run；三个定义会产生完全不同的地图节奏。
- 星级存档属于局外进度，需要单独 schema、迁移与平台云存档边界，不能塞进当前手内 Run 存档。

## 最小下一步

先做一张不可持久化的章节选择原型，只验证信息架构：

- 4 个普通节点 + 1 个 Boss 节点。
- 每个节点只显示名称、特色规则、过关目标和三颗空 / 实星。
- 入口同时提供`闯关模式`和`自由模式`，但先不做正式解锁与奖励。
- 用手机测试玩家是否能在 3 秒内指出“当前关、下一关、Boss、星级要求和自由模式入口”。

通过后再决定正式关卡单位、首章数量、星级条件、解锁奖励和局外存档；未通过则只保留现有短局入口。
