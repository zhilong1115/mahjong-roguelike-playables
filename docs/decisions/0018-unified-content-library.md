# 0018 — 五系功能卡统一 Library

状态：`Accepted`（内容管理技术决定；五系玩法、单卡数值仍为 `Proposed`）

日期：2026-07-26

## 要解决的问题

五系功能卡原本分散在五个模块中，虽然已有统一查询入口，但新增、下架、改价和图鉴展示仍可能发生清单不一致。内容扩张后，最危险的情况是商店能抽到 UI 或效果解释器不认识的卡，或者删卡后旧存档无法解析。

成功信号：

- 五系所有现行卡只有一份数据源。
- 抽签、商店、计分、图鉴和测试读取同一个对象。
- 重复 id、未登记 effect、缺文案、非法签阶或价格在启动或测试时直接报错。
- 下架卡不进抽取池，但仍可被旧存档按 id 解析。

## 决定

1. `src/content/library.mjs` 中的 `CONTENT_LIBRARY` 是灵签、番谱、福将、牌骨、牌印的唯一数据源。
2. 每张卡都带稳定的 `family + id`、`enabled`、`status`、`pools`、`weight`、持续时间、卡面文案和效果描述。
3. `enabled: false` 表示下架；它会从抽签和商店列表消失，但 `getItem` 仍可查到。只有配套存档迁移后才能硬删除 id。
4. 关卡、圈主、手气、牌组和牌帖不属于五系功能卡，保持独立内容表，但仍由 `content/index.mjs` 统一对外查询。
5. 游戏内增加「百牌谱」，五系页签与卡牌数量直接来自 Library，不手写第二份图鉴清单。

## 后果

- 普通数值卡的新增、调价、改文案和下架只需改 Library 记录。
- 新 effect kind 仍需在规则解释器或事件处理器实现，并同时登记到 Library 校验集合中。
- 动态改命签还需合法目标生成、预览、确认交互和存档字段；统一 Library 不等于这些牌已经实现。

## 回退条件

如果内容超过约 80 件后单文件明显阻碍合并或编辑，可以把各系数据拆回多文件；但对外仍必须组装成同一个 `CONTENT_LIBRARY`，校验、下架和存档兼容规则不变。
