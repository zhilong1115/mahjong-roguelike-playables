# 0021 · 局内可读性：开运位、弹窗尺寸、结算节奏、常驻栏与牌骨材质

状态：`Accepted`（实现完成）
日期：2026-07-27

## 背景

`0019` 之后用户完整玩了一局，提了五条：

1. 牌桌中央已经摆着亮出的碰 / 顺 / 杠，顶部开运位再摆一份是重复，那里应该只显示灵签。
2. 求签和百宝阁的弹窗还是太小。它们是一次性弹窗，选完就消失，应该像云顶之弈选强化符文那样占满屏幕。
3. 结算动画太快，而且看不出顺序：结算到灵签时上面的灵签应该跳一下，结算到百牌时对应的百牌应该跳一下。
4. 常驻构筑栏里番谱不用平铺，点一下看当前番率就行；牌骨也是点一下，看各个材质分别改了哪些牌；福将要一位一卡地单独显示。
5. 牌骨的变化在牌面上看不出来。

这一轮同样不动规则数值、状态机和存档 schema，只改表现层。

## 决定

### 1. 开运位 = 灵签栏

`renderSlots()` 不再画 `groupTiles`。已花掉的开运位显示：灵签印章 + 签名 + `签阶 · 组合类型`，
签阶决定顶边颜色（银 / 金 / 彩）。亮了组但签池不足没拿到签时，退回一个 `已花掉 · 无签` 的占位，
玩家仍然知道这个位子花掉了。

同时给每个带签的开运位写上 `data-charm-index`（按取得顺序），结算时才能精确命中是哪一格，
同名签也不会认错。

### 2. 求签层与百宝阁按「一次性弹窗」放大

| | 之前 | 现在 |
|---|---|---|
| `#draftPanel` 宽 | 760px | 1240px |
| 灵签卡 | 212×244 | 320×430（`min-height:min(430px,58dvh)`）|
| 标题 | 14px | 24px |
| 商店 `screenBox` | 默认 | 1240px / 94dvh，`#shopGrid` 改成三列 grid |
| 商店卡 | 174×214 | 320×420，价格牌移到卡右上角 |

正文 11px → 14px，卡名 15px → 22px，印章图 60×76 → 90×114。
矮横屏（≤470px 高）与窄屏各留一档缩小值，保证 390px 高度里标题 + 卡 + 按钮仍是一屏。

### 3. 结算节奏分档，并且「先跳卡，再飘数字」

- 原来所有步骤一律等 190ms。现在按 `STEP_BEAT` 分档：组合底分 210ms 最快，
  灵签 460ms、番种 480ms 最慢——值得看的步骤给足时间。
- 每一步先 `pulse` 锚点（跳 + 一圈金色 `spotlight` 高光），等 `STEP_LEAD = 130ms`，
  再飘 `+牌值 / +番 / +金`。跳和数字分开，因果关系才看得出来。
- `findStepTarget` 换成 `stepAnchors`，返回**一组**锚点而不是一个：
  - 灵签 → 顶部对应的开运位（按 `data-charm-index`）
  - 福将 → 常驻栏里那一张将位卡
  - 番谱 → 常驻栏的番谱摘要
  - 牌骨 / 牌印 → 牌桌上所有该牌种的牌 **加上** 常驻栏的对应摘要，一起亮
- 收尾也放慢：乘式停 520ms、总分滚 1000ms、落地停 950ms。

一副典型牌的结算从约 4 秒变成约 8.5 秒，点一下仍然可以快进。

> 顺带修了测试的一个坏味道：`src-viewport-smoke.mjs` 原来用固定 `sleep(4200)` 等结算屏，
> 每次调节奏都要回来改。换成 `waitUntil` 轮询实际条件。

### 4. 常驻构筑栏：能平铺的平铺，按牌种铺开的收起来

- **福将**：一位一卡，两列排，空将位也画出来。将位是有限资源，必须一眼数得清。
- **番谱 / 牌骨 / 牌印 / 牌帖**：这些是「按番种或按牌种铺开」的东西，平铺既占地方又读不出来。
  收成一排可点摘要（`.buildChip`），点开一个轻量弹层 `#sheet`：
  - 番谱 → **番率表**：所有番种的番势，以及番谱把哪几种练到了几级；当前手牌命中的行会高亮。
  - 牌骨 / 牌印 → 按牌种铺开，**左边直接画那张牌**（带上它的材质和印记），右边写改了什么。
  - 牌印额外写出触发时机（换出时 / 亮组时 / 成胡时）。
- 摘要那一排放在 `#buildChips`，在滚动区之外——福将占满时它也必须还看得见。

牌印用户没点名，但它和牌骨同构（都是「买一张，选一个牌种装上」），所以按同一套处理。

### 5. 牌骨改成真的换材质

牌骨原来只是牌底一条 3px 彩带，等于没有。现在 `tileBody()` 接受 `material`，直接换掉整张牌的料子：

| 牌骨 | 材质 | 表现 |
|---|---|---|
| 温玉骨 | `warmJade` | 面色青白的玉料，托板亮玉绿，左上角一枚玉色记号 |
| 青竹骨 | `greenBamboo` | 面色黄绿的竹料，**带竖向竹纹**，托板竹绿，左上角竹色记号 |

牌印同时在牌面右上角盖一枚朱砂小印。`createTileCanvas` 新增 `{material, sealed}`，
缓存 key 带上它们；`app.mjs` 里所有牌一律走 `tileCanvas()`，按 `state.bones / state.seals`
自动查当前牌种的皮肤，不会有的地方画有的地方不画。

## 影响与验收

- 规则、数值、存档 schema 未动。`node --test tests/*.test.mjs` 132 项全绿。
- `node tests/src-viewport-smoke.mjs` 33 项全绿：无裁切、无遮挡、无页面滚动，最小可点 ≥44×48px。
  求签卡从 158–212 × 193–244 变成 152–320 × 206–430。
- 本轮与另一位 agent 的 `0020`（原型福将与强度曲线）在 `src/ui/app.mjs` 上撞车，
  已按三方合并手工解开，两边改动都在。

## 没做的事

- 结算顺序本身没改，仍然是 `0011` 的八步。用户说的「合理顺序」在实现上是「看得出现在算到谁」，
  所以做的是锚点高亮而不是重排流水线。
- 牌骨材质目前只有两种，因为内容池里只有两张牌骨。加牌骨时必须同时在
  `TILE_MATERIALS` 里加料子，否则会静默退回象牙面。
