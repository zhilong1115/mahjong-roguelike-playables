# 0015 — 银签、金签、彩签与待缘签兆

状态：`Proposed`

日期：2026-07-26

实现：最小可玩切片已进入 `src/`，包含固定签阶、鸿运、广缘、单格待缘位、替换确认、完整签局快照和 schema v4。概率与玩法仍未经过真人验证，本记录继续保持 `Proposed`；`0014` 的改命签、天眷签和通用触发引擎尚未实现。

纸面与工程复核：`docs/playtests/2026-07-26-charm-tier-omen-paper-review.md`。

最小切片实现检查：`docs/playtests/2026-07-26-charm-tier-omen-implementation-check.md`。

## 与现有提案的关系

`0014` 把灵签分成 `助势 / 改命 / 奇缘` 三种职责，其中前两条是主要价值线。本记录增加第二个独立维度 `签阶`，并允许部分奇缘签留下一个跨副保留、触发一次后消失的 `签兆`。

这会对“所有灵签只持续本副”形成一个明确例外：灵签卡本身仍在取得时结算并消失；只有卡面写明的签兆进入一个单独的 `待缘位`，持续到本局下一次匹配事件。它仍由灵签产生，不是第六类商店内容。

## 要解决的问题

1. 求签需要有“翻到稀有好签”的瞬间期待，但不能让玩家只看颜色无脑选彩签。
2. 奇缘位除了高波动分数和返金，还应能让玩家押注下一次求签，形成跨两次亮组的小组合。
3. “幸运提高”和“下次多一个选项”必须让玩家看得见何时生效、何时消耗，并且不能靠重抽、读档或失败重试反复领取。

## 两个互相独立的维度

每张灵签同时具有：

```text
职责：助势 / 改命 / 奇缘
签阶：银签 / 金签 / 彩签
```

- 职责回答“这张签做什么”。
- 签阶回答“这张签多稀有、效果上限多高”。
- 金签或彩签不保证比当前银签更适合牌面；适配的银签仍可能是正确选择。
- 第一版让每个签名拥有固定签阶，不把同一张签简单复制成 `+20 / +40 / +80` 三个数字版本。未来如果某张签需要升阶版，再为它单独记录变化。

### 签阶边界

| 签阶 | 设计职责 | 不只靠颜色的识别 |
|---|---|---|
| 银签 | 一个直接、稳定、容易心算的效果 | `银签`文字、单层边框、1 枚签纹 |
| 金签 | 更强保证、更多目标或一次可控的未来收益 | `金签`文字、双层边框、2 枚签纹 |
| 彩签 | 改变一次规则，或组合两个紧密相关的效果 | `彩签`文字、放射签头、3 枚签纹 |

彩签不能同时提供“保证胡牌、升级大胡、直接爆分”三种收益。它应该强而有条件，而不是见到就必选的答案。

## 首轮签阶生成

第一版不让三个位置各自独立抽稀有度，而是每次求签先抽一个整体签阶版式：

| 版式 | 纸面概率 | 三个位置 |
|---|---:|---|
| 银局 | 72% | 银 / 银 / 银 |
| 金局 | 25% | 银 / 银 / 金 |
| 彩局 | 3% | 银 / 银 / 彩 |

- 金签或彩签的位置在三个合法职责之间按 seed 分配，不固定出现在奇缘位。
- 同一次普通求签最多出现一张金签或彩签，避免三张独立抽阶造成稀有签泛滥。
- 不因为这是本副第几次亮牌而提高概率，也不加入隐藏保底；否则会进一步鼓励机械地亮满六次。
- 先按助势、改命和奇缘建立合法候选池，再按签阶版式从对应固定签阶的池中取内容；没有合法目标的改命签仍不能出现。
- 若所抽高阶在当前所有合法候选中都没有内容，普通签局允许降阶，不能因牌池不足免费升阶。由签兆明确保证高阶时，则必须保留签兆直到能成功应用，不能静默浪费。
- `问签印`重抽只更换签的内容，不能重新抽签阶版式；只要当前合法池存在另一组完整结果，重抽后至少一张签必须变化。

以 3% 彩局为纸面起点，亮满六次时至少见到一次彩签的概率约为 16.7%。该数字只是避免彩签过密的第一版锚点，必须和亮牌次数分布一起模拟。

第一局教学牌谱固定为银局，不在玩家学胡牌时同时教学稀有度。

## 奇缘留下“签兆”

部分奇缘签不提供当前得分，而是把一个一次性效果放进 `待缘位`：

```text
待缘位为空
→ 选择延时奇缘
→ 留下一个签兆
→ 跨副、商店和关卡保留
→ 下一次匹配的求签打开时自动应验
→ 效果写入该次签局，待缘位清空
```

首版只有 **1 个待缘位**：

- 签兆不排队、不叠加，也不能手动选择触发时机。
- 待缘位已有内容时，选择另一张延时奇缘会显示替换预览；确认后新签兆覆盖旧签兆，取消则回到原三签。
- 同名且没有额外收益的签兆在待缘时不再进入候选池。
- 本局最后一次可能求签时，不出现“强化下一次求签”的死签。
- 完整一局结束或主动开始新局时清空。
- 本关失败后重试时，恢复进关前的待缘状态：失败尝试里新取得的签兆不能带回去刷，进关前已有而在失败尝试中消耗的签兆也应恢复。

签兆的玩家文案必须同时写清范围和消费事件，例如：

```text
本局 · 下一次求签时应验并消耗
```

## 首批延时奇缘

| 名称 | 签阶 / 职责 | 签兆效果 |
|---|---|---|
| 鸿运签 | 金 · 奇缘 | 下一次求签至少出现 1 张金签；该保底位有 15% 升为彩签。签局打开时消耗。 |
| 广缘签 | 金 · 奇缘 | 下一次求签从三选一变为四选一；第四张为银签随缘位，仍然只能选 1 张。 |
| 天眷签 | 彩 · 奇缘 | 下一次求签四选一，并至少出现 1 张金签；该保底位有 25% 升为彩签。 |

第一版先实现 `鸿运签 + 广缘签`。天眷签等两条单效果的状态、存档和界面稳定后再加入，避免第一次实验同时测试“组合签兆”。

这三张都没有当前副即时加分，也不直接改变手牌。玩家是在眼前的助势 / 改命与未来一次更好的求签之间选择。

为了让 3% 彩局在改命签尚未实现时仍能真实生成、展示和完成结算，当前切片另加入一张实验占位卡：`虹福签（彩 · 奇缘）`，本副番势 +1，并立刻 +1 待结算金币。它不留下签兆，不代表最终彩签强度；真人试玩后可以改写或删除。

## 四选一的规则

广缘签应验时，本次签局固定为四个位置：

1. 助势位。
2. 动态合法的改命位；无合法目标时回退为助势。
3. 奇缘位。
4. `加签位`：从当前合法池取得一张与前三张不同的银签，职责不限。

- 四张中仍只能选择一张。
- 第四张首版固定为银签，避免“多看一张”同时暗中增加高阶签概率。
- 问签印重抽后仍是四选一，四个签阶位置不变，只替换合法内容。
- 数字键扩展为 `1 / 2 / 3 / 4`；Esc 返回不重新生成签局。
- 当前合法内容不足四张时，广缘签不应被消耗；扩池时必须保证固定测试牌谱至少有四张不同合法签。

## 消费和防连锁规则

消费时点固定为“下一次新的求签界面成功生成并打开”：

1. 读取待缘位。
2. 生成 `offerCount`、锁定签阶位置和合法内容。
3. 把签兆效果复制进本次签局快照。
4. 保存完整签局后清空待缘位。

玩家已经看见第四张签或高阶保底时，收益就已经交付；最终选了哪张不影响签兆是否消费。

- 新取得的签兆只影响下一次独立求签，不能回头改变当前三签。
- 首轮被签兆强化的签局不再出现会留下新签兆的奇缘，防止 `鸿运 → 鸿运` 或永久四选一续杯。
- 同一副最多应验一次签兆；其他求签按普通规则生成。
- 问签印重抽不算新的求签，不再次消费签兆，也不重新抽签阶。
- 旋转、后台恢复和读档不算新的求签。

## 与现有系统的关系

### 开运位和金币

玩家选择签兆时已经花掉一个开运位，却没有获得当前副加分或改命；要兑现又必须在之后再次亮组。因此它天然是一次未来押注。仍要用固定牌谱验证高阶期待不会让“全亮找彩签”同时赢得分、过关率和金币。

### 改命签

签阶不放宽 `0014` 的合法目标边界。金 / 彩改命可以增加选择自由度或保证程度，但不能显示非法目标，也不能改变本体牌种与有效牌种的分工。

### 问签印

本次签局首次打开时即锁定 `offerCount` 和签阶位置。问签印可以重抽内容，不能把银局刷成金局或彩局。

### 手气“签气”

当前实现会从对子本组签里固定取到双喜签，并不是真随机。进入本提案的最小实现时，签气改为专用即时池，首版固定给予一张银色助势签；不会自动给改命、彩签或签兆，也不会消费待缘位。

## 最小工程方案

不需要先建立任意事件触发引擎。首版只增加两个明确状态对象：

```text
pendingOmen = null | {
  omenId,
  sourceCharmId,
  acquiredAtBlind,
  consumeOn: "nextCharmDraft"
}

draft = {
  draftId,
  offerCount: 3 | 4,
  tierSlots,
  appliedOmen,
  offers: [{ offerId, charmId, tier }],
  ...现有的 groupId / slotIndex / rolls / reroll 数据
}
```

- 内容与签阶使用不同的 seed salt，增加第四张不会把后续所有随机结果一起推移。组合 seed 后还要经过稳定的 32-bit avalanche 混合，不能直接把相邻玩家 seed 喂给随机函数的首个输出。
- 生成后的 `offers`、顺序、签阶和 `appliedOmen` 全部存档，恢复时不重新计算。
- 已取得灵签从纯 `charmIds` 升为带实例 ID 和签阶的 `charmInstances`，结算和卡面读取实例而不是只读内容 ID。
- 在进入本关时保存待缘位轻量快照；重试时恢复，避免失败刷签兆。
- 本记录的签阶 / 签兆已经使用 schema v4；v3 的 `charmIds` 按新版内容表补上固定签阶，数值效果保持不变，旧 draft 保留原三个内容 ID 并补齐各自签阶，不能重新抽取。`0014` 将来实现时继续扩展 v4 的有效牌种与改命目标字段。
- 本地存档升级时继续读取旧的 `tianhu.run.v3` 键，成功写入 v4 后再迁移，不能让玩家看起来像丢档。
- 打开签局、消费签兆、问签重抽、确认选签都要即时存档，不能只依赖普通的延迟保存。

## 交互和响应式边界

- HUD 增加一个紧凑 `待缘位`，显示名称、`下次求签`和`一次`；它不混入六个开运位。
- 卡面同时显示 `[银签 / 金签 / 彩签]` 与 `[助势 / 改命 / 奇缘]`，不能只靠颜色。
- 待缘位被占用时选择新签兆，显示当前 / 新签比较以及 `返回选签 / 换成新缘`。
- 844×390 横屏让三张或四张签横排；360×800 和 390×844 竖屏用 `2+1` 或 `2×2`，不横向滚动。
- 求签层移到 `#app` 根级固定决策层，不能继续放在会裁切 360×800 的 `#table` 内。
- 所有签卡、目标和确认按钮至少 48×48 CSS px；灰度画面中仍能凭文字、签纹和轮廓辨认签阶。
- 普通三选一平均仍以 5 秒为目标；四选一平均以 6 秒、包含替换确认以 8 秒为目标。

## 主要风险

1. **追彩签导致机械全亮**：求签次数本身增加见高阶签机会。首轮不做随亮牌次数增长的幸运，也让加签位固定为银签。
2. **彩签成为自动答案**：彩签必须有条件或延迟兑现；展示后的选择率若长期超过 80%，就需要削弱或收窄条件。
3. **签兆跨副模糊五系边界**：UI 必须把待缘位标成灵签留下的“一次性状态”，不能伪装成第五个福将或新商品。
4. **替换与连锁拖慢节奏**：只有一个待缘位，首轮禁止强化签局继续产生签兆。
5. **失败与读档刷取**：重试恢复进关快照，求签关键操作即时存档，签阶与内容由独立 seed 决定。
6. **四选一挤爆窄屏**：先修现有三签裁切，再用根级 2×2 决策层实现四签。

## 成功信号

- 玩家能说清：“助势 / 改命 / 奇缘是功能，银 / 金 / 彩是稀有度。”
- 至少 4 / 5 名陌生玩家能指出待缘什么时候触发、只用一次，以及新签兆会替换旧签兆。
- 普通三选一平均不超过 5 秒，四选一不超过 6 秒，替换确认完整流程不超过 8 秒。
- 签兆选择率约 15%–45%，并且至少 80% 的已选签兆能在本局结束前兑现。
- 彩签展示后的总体选择率在 45%–75% 之间；固定牌谱中至少有一局会合理选择更适配的银签或金签。
- 固定 seed 和存档测试证明：最多一张高阶签、四张不重复、问签不刷签阶、签兆只消费一次、失败重试不刷取。
- required 六视口的普通三签、四签、待缘替换和改命目标均完整可见可点；关键目标达到 48×48px。
- 对比 0、2、4、最大亮牌路线时，最大亮牌不能同时稳定赢得分、过关率和金币。

## 接受或回退条件

只有完成固定 seed 概率模拟、schema v4 迁移测试、required 视口检查和真人试玩后，才能把本提案提升为 `Accepted`。

- 若玩家仍把彩签视为必选：把彩签从无条件强效改为窄条件或延迟效果，而不是只调低出现率。
- 若签兆兑现率低于 80%：提高可触发机会、缩短触发条件，或回退为只在本副内使用的消耗签。
- 若一个待缘位仍让玩家忘记：把延时奇缘回退为“下一次亮组立即触发”的本副效果，不跨关保留。
- 若四选一显著拖慢或挤压界面：保留幸运保底，删除加签效果。
