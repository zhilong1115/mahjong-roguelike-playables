# 0024 · 美术重绘、开运签牌与单牌亮组

状态：`Accepted`（用户确认问题与方向；首轮实现完成后仍需手机审美试玩）

日期：2026-07-29

## 要解决的问题

背景 shader 与弹簧动效已经让画面动起来，但麻将牌、牌背和功能卡仍主要依赖系统字体、纯色框与同系单字，
看起来更像完成度较高的网页原型，不像有独立美术身份的游戏。局内还有两处比例问题：

1. 顶部开运位太矮、太横，拿到的灵签缩成一条文字，既不像签牌也不够醒目。
2. 牌桌中央把亮组的所有实体牌再次铺开；亮满时重复牌占据大量空间，却没有突出“亮的是对子、顺子还是杠”。

成功信号：玩家第一眼能把麻将牌、灵签与福将当成三类不同的实体物件；已亮组合在最多四组时成为牌桌视觉主体；
六个开运位仍可数清，横竖屏关键按钮不被挤出视口。

## 决定

### 1. 麻将牌与牌背继续使用确定性 Canvas，但完整重绘

- 牌面保持规则可读优先，不使用生成式图片绘制牌种。
- 加宽牌身与瓷面，重做面釉、倒角、侧边、托板、刻痕与材质层次；万、筒、条、字牌继续由同一渲染器输出。
- 四套牌背改成雕漆 / 景泰蓝式的双框、角花与中心纹章，仍与牌面共享相同立体牌身。
- 牌骨和牌印继续叠加在这套统一牌身上，不能回退成牌外标签。

### 2. 功能卡使用“真实卡图 + 物理品类”

- 灵签使用 5×4 的原创签纹图谱，每张现行灵签拥有稳定、独立的图案位置；卡壳表现为旧签纸、朱砂、金箔与墨迹。
- 福将使用 4×3 的原创神将头像图谱，十一位福将各自拥有稳定头像；最后一格保留为空将位神龛。
- 番谱、牌骨、牌印继续用代码绘制，但分别表现成线装书、材质牌坯和朱砂印，不再共用一个方框单字。
- 所有图像保存在 `src/assets/`，运行时不请求外部字体或图片服务；内容 id 与图谱位置映射留在渲染层，不污染规则 Library。

### 3. 开运位改成更大的短签牌

- 六个位置仍同时可见；横屏保持一排，竖屏保持 3×2。
- 增加高度、减小宽高比；已取得的灵签显示图案、签名与签阶，空位仍明确显示金币价值。
- 开运位只显示灵签，不重新塞回亮组实体牌；沿用 `0021` 的信息分工。

### 4. 亮组只显示一张代表牌 + 水墨组名

- 对子 / 刻子 / 杠取第一张为代表；顺子取中张为代表。
- 牌面明显放大，每组上方显示水墨字：`对 / 顺 / 碰 / 杠`。
- 渲染器同时预留 5–8 张同牌的显示名：`五 / 六 / 七 / 八`。这只是表现兼容，不表示 `0016` 的叠杠规则已经实现。
- DOM 继续记录该组全部牌种，让牌骨、牌印和结算高亮仍能定位到这张代表牌。
- 标准四组时优先单排；七对路线或未来超过四组时允许紧凑换行，不能溢出牌桌。

## 资产来源与原创边界

- 两张图谱由 OpenAI 图像生成工具按本项目“旧式电子麻将馆 × 庙会求签 × 神将牌局”方向生成，
  再压缩为项目内 WebP；不包含第三方游戏角色、商标或可识别卡图。
- 不复制《小丑牌》的小丑形象、扑克卡面、CRT 构图或整体视觉外观；借鉴的只有卡牌拥有独立插画、触发反馈清晰等抽象原则。

## 验收与回退

- `config/viewports.json` 六个 required 视口全部无页面滚动、关键内容裁切或按钮不可点。
- 844×390 中六个开运位、最多四个大亮组、14 张手牌和操作按钮可同时完成操作。
- 360×800 中开运位 3×2，亮组可换行，状态不因 resize 重置。
- 若图谱让首帧超过目标或在低端设备解码明显卡顿，优先降低 WebP 分辨率/质量，不回退到同字印章。
- 若真人认为风格过于写实或与牌桌不统一，只替换图谱，不改内容 id、规则或卡片结构。
