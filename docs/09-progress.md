## 现在能玩到什么

正式版骨架与 `0017` 六关短局已经可以完整走通：`src/index.html`。圈关规则仍是
`Proposed`，实现完成不等于已经接受。

```bash
node tools/dev-server.mjs
```

打开 `http://127.0.0.1:4173/src/`，加 `?seed=数字` 复盘同一局，加 `&intro=0` 跳过玩法说明。

- 标准局为东 / 南两圈，每圈依次经过闲局、庄局、圈主三关，每关只打一副；通关后可选西圈加赛。
- 闲局和庄局可跳过换一张手气；圈主必须打，并带一条开打前可见的单变量规则。
- 每个打赢的非最终关后进入百宝阁；标准全打六副、五家商店，西圈加赛再增加三副、两家商店。
- 每副 14 张结构牌、5 次**换牌机会**（一次可换多张，没用完的每次胡牌换 2 金）、默认 6 个开运位；亮组通常三签选一，广缘兆应验时四签选一，合法时可胡。
- 牌墙预览张数跟着起手打碎张数走：东圈看 2 张，南 / 西圈看 3 张；圈主「独眼张」会遮住预览。
- 灵签同时显示银 / 金 / 彩签阶与助势 / 奇缘职责；鸿运和广缘会留下一个跨副保留、下次求签消费的待缘兆。
- 单副达到本关目标后，待结算金币与过关金入账；得分仍为 `牌值 × 番势`。东 / 南目标为 400/550/700 · 800/1350/2200，西圈加赛为 1000/1450/2400。
- 开始界面可继续存档或选择四种牌组；当前存档 schema 为 v4，并兼容读取 v1–v3。
- 标题页和局内都可打开「百牌谱」；现行 24 张五系卡由同一 Library 供抽签、商店、计分和图鉴使用。

## 怎么验收

环境要求：Node.js 22+；required 视口 smoke 还需要本机 Chrome。项目目前没有 npm 安装步骤。

```bash
node --test tests/src-*.test.mjs     # 正式版规则 / 结算 / 圈关 / 存档 / 集成
node tests/src-viewport-smoke.mjs    # 正式版 required 视口与关键界面流程
node --test tests/*.test.mjs         # 可选：再加历史原型规则回归
```

`KEEP_VIEWPORT_ARTIFACTS=1` 可以保留截图目录。原型自己的 viewport smoke 是历史对照，不替代正式版检查。

## 下一步（按优先级）

1. **真人试玩六关短局**：记录标准局总时长、每副求签数、五家商店停留与购买数、失败位置、跳局理由和西圈进入率。
2. **第一张改命签切片**：先做借张签的动态合法目标、预览、确认与存档，证明 Library 能承载不只是加分的功能卡。
3. **商店抽卡切片**：设计可购买的普通 / 金 / 彩签筒或牌包，买后多选一；同时测试开局免费三选一，让构筑反馈更早出现。
4. **验证外层内容**：确认圈主规则是否一眼可懂、四种牌组是否都有代价、手气是否值得放弃一关与一次商店。
5. **验证五系可读性**：观察番谱、福将、牌骨、牌印是否能被区分，再决定稀有度和扩池。
6. **验证新版灵签**：先真人试玩鸿运 / 广缘 / 虹福，记录签阶辨识、待缘兑现率、三 / 四选一时间和彩签选择率；随后再实现 `0014` 的第一张动态改命签，不先扩展天眷。
7. **验证叠杠想法**：用固定牌谱测试 4 / 5 / 6 / 8 张同牌与十四归一；确认补牌、开运位、求签次数和拆分路线后，再决定是否进入代码切片。
8. **打包与平台**：产出自包含 `dist/`、记录体积，再用最新官方文档补 YouTube Playables / TikTok 生命周期适配。
9. **教学**：首局先教胡牌与灵签，商店和后续关卡再逐步揭示长期商品、跳局与圈主。

## 已知问题

- `0017` 仍为 `Proposed`；六关短局和西圈加赛不是已冻结规格。
- 六关自动路线通关率为 82.5%–92.5%，目标可能偏松；尚无真人 5–8 分钟完整局计时。
- 标准局只有五家商店，长期商品能否及时兑现、价格是否适合较低收入仍未验证。
- 开局三选一和商店签筒 / 牌包尚未实现，所以当前只是提高了商店频率，还没有完成用户期待的抽卡型商店。
- 固定职责货架是实验设定，不是正式规则；牌帖也只是当前无持久实体牌库时的过渡方案。
- 自动试玩 AI 在圈关流程下流局率约 1%（修好七对打碎上限与预览张数之后）；真人流局率未知。
- `0014` 的借张、移花、归一和听风尚未实现，因此当前签面虽然显示新职责框架，实际可选内容只有助势与奇缘。
- 虹福签只是让彩签能真实生成、展示和结算的实验占位卡；72 / 25 / 3、鸿运 15% 升彩与虹福数值都没有真人数据。
- 当前 11 张签能保证普通 / 广缘签局有足够合法内容；以后删签或收窄候选池时，必须先加“亮组前可生成完整签局”的 invariant 或事务回滚，不能让亮组完成后才发现签池不足。
- `0016` 的叠杠与十四归一只是设计记录；当前四张同牌上限、胡牌判定和 schema v4 均未为它改动。
- 2026-07-26 已修复 360×800 求签裁切，并把 smoke 扩展为 overflow 祖先可见交集、中心点遮挡、三 / 四签六视口与 `1–4 / Esc`。牌桌部分旧控件在矮横屏仍约 44–45px；新增待缘位和签卡达到 48px 目标。
