# 签阶与待缘最小切片实现检查

日期：2026-07-26

版本：当前工作树，`0015` 最小可玩切片

性质：规则、存档与响应式自动检查；不是陌生玩家玩法试玩

## 假设

银 / 金 / 彩签阶、单格待缘位、鸿运和广缘可以在不建立通用触发引擎的情况下接入现有求签流程，并且满足以下底线：

- 同一 seed 可复现，问签重抽不能刷签阶。
- 签兆只消费一次，失败重试与读档不能刷取。
- 广缘四选一在横竖屏都完整可点，仍然只取得一张签。
- 玩家不需要只靠颜色辨认签阶。

## 本次实现

- 11 张测试签都有固定 `tier` 与 `functionRole`；普通签局采用 72% 全银、25% 一金、3% 一彩的实验版式。
- 直接增加牌值 / 番势的倍喜、余裕等标为助势；财神、虹福与延时签兆标为奇缘，底层旧货位 `wild` 不再自动等同于卡面“奇缘”。
- 新增金签鸿运、金签广缘和实验彩签虹福。
- 新增单个 `pendingOmen`、完整 `draft.offers` 快照、签实例、替换确认和本关入口待缘快照。
- 存档升级为 schema v4；旧 v3 签局保留原签与顺序，只补签阶和实例，不重新抽取。
- 求签层从牌桌内部移到 `#app` 根级；竖屏普通三签为 `2+1`，四签为 `2×2`。

`0014` 的借张、移花、归一和听风没有在本次实现，当前可玩职责只有助势与奇缘。

## 自动检查结果

- `node --test tests/src-*.test.mjs`：66 / 66 通过。
- `node tests/src-viewport-smoke.mjs`：required 六视口通过。
- 连续 20,000 个正式 seed 的普通签局实测为银局 72.06%、金局 24.99%、彩局 2.95%；连续 12,000 个鸿运签局的升彩率为 15.14%。这些是实现分布检查，不替代真人平衡测试。
- 普通三签与广缘四签均检查了：viewport 与 overflow 祖先的实际可见交集、中心点遮挡、页面滚动、签阶文字、1 / 2 / 3 枚签纹和触控尺寸。
- 数字键 `4` 能选择广缘的第四张；替换确认在 360×800 与 844×390 都达到 48px，按 Esc 会回到同一个 `draftId`、同一组 offers 和签阶，不会重抽。
- 延时奇缘卡明确显示“本局 · 一次”，待缘位可点击回看完整效果；选签或替换结束后会通过 live toast 宣告，并把键盘焦点送回可用的主要操作。
- 恢复到求签中的 v4 存档时，标题 / 帮助屏会把底层求签设为 hidden、inert 和 aria-hidden；`1–4 / Esc / Enter` 在点击继续前不能暗中改签局，继续后才恢复焦点与操作。
- schema v4 往返、v1 → v4、v2 → v4、v3 → v4、本地 v4 优先 / v3 回退均通过；v4 JSON 损坏但迁移期 v3 尚在时也会继续尝试旧档。

## 实现中发现并修正

- 旧求签层位于 `#table` 内，被 `overflow:hidden` 裁掉 360×800 的卡面；现已改为根级 fixed 决策层。
- 更严格的中心点检查发现 844×390 选关页的“返回标题”覆盖“跳局”；现已移到面板右上角，不再占据卡片操作区。
- 求签打开、签兆消费、问签重抽、替换确认和选签期间改为立即写存档；普通操作继续合并延迟保存。
- 所有平台存档写入经过同一串行协调器；即使平台 `save` 是异步 Promise，旧请求也不能晚完成后覆盖新状态，单次失败不堵塞后续保存。
- 本地 v4 JSON 若在迁移期损坏，会继续尝试仍存在的 v3，而不是直接放弃恢复。
- 相邻 seed 先经过稳定的 32-bit avalanche 混合再进入签局随机流，修正了旧做法首个随机数高度相关、稀有签成片出现的问题。这个调整只改变尚未生成的未来签局；已经打开的签局保存完整 offers，因此读档不会变签。
- 问签如果随机结果刚好与原三 / 四张完全一致，会在保持签阶、职责、张数和不重复约束下寻找一个确定性的替代组合；只要合法池中存在另一组结果，玩家就一定会看到至少一张变化。极少数走到该回退路径的结果会受内容表稳定顺序影响。

## 尚未验证

- 真人能否快速区分“签阶”和“职责”。
- 鸿运 / 广缘是否值得放弃当前加分，待缘兑现率是否达到 80%。
- 72 / 25 / 3、鸿运 15% 升彩和虹福强度是否合适。
- 四选一是否把平均选择时间推高到 6 秒以上。
- 稀有签期待是否进一步鼓励机械地亮满六次。

## 结论

最小框架在规则、存档和 required 视口上成立，可以交给玩家试。它证明“能够实现”，不证明当前概率、虹福数值或长期玩法已经合理；`0015` 继续保持 `Proposed`。

下一次实验只记录真人数据：签阶辨识、三 / 四选一时间、签兆选择率、兑现率、彩签选择率和每副亮组次数。在这些数据出来前不加入天眷签。
