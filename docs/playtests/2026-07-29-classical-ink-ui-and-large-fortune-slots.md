# 2026-07-29 · 古典水墨界面与大开运位屏幕检查

状态：`Automated Layout / Visual Review`（不是玩家审美结论）

## 验证目标

1. 标题页、牌桌、麻将牌、牌背、Logo 与 UI 框架使用同一套宣纸 / 淡墨 / 旧木 / 温玉 / 朱砂语言。
2. 六个开运位比上一版明显更大，并主动占用牌桌面积，而不是继续作为顶部细栏。
3. 放大开运位后，required 六视口仍可看见亮组、牌墙、14 张手牌与主要操作，没有页面滚动和关键裁切。
4. 新背景保持离线、自包含和可接受体积，不改变规则、存档或 Library id。

## 方法

- 为标题页与牌桌全新生成两张无字水墨背景，转成本地 WebP；中文 Logo 由 Canvas 单独绘制，避免生成图中的错误文字。
- `tests/src-card-art.test.mjs` 检查两张水墨 WebP 存在且总大小低于 900 KB。
- `tests/src-viewport-smoke.mjs` 在 `config/viewports.json` 的六个 required 视口检查页面滚动、遮挡、手牌溢出和操作可达性，并读取开运牌架与最小格子的实际高度。
- 保留并人工查看标题页、牌局、亮组、求签、请将台与百牌谱截图；额外检查 844×390、360×800 与 1280×720 的密度。
- 运行正式版规则 / UI 测试与全仓回归，确认纯视觉改动没有改变牌局行为。

## 结果

- 水墨背景合计约 306 KB，远低于 900 KB 门槛，页面没有新增外部字体或运行时图片请求。
- 1280×720 与 960×960 的开运牌架实测为 132px 高、最小格 106px；844×390 为 88px / 72px；360×800 为 132px 的 3×2 牌架、最小格 56px；较宽竖屏单格为 64px。
- 六视口均无页面级滚动、关键裁切、手牌溢出或中心点被遮挡；844×390 同屏保留六个大开运位、亮组、牌墙、14 张手牌和主要按钮。
- 标题页的月、山、竹与宣纸菜单保持层级清楚；牌桌中央的低对比负空间足以承载最多四个单牌亮组。
- 正式版 84 项、全仓 137 项和 required viewport smoke 全部通过。

## 尚未验证

- 自动截图只能证明布局、资源与对比没有明显故障，不能证明用户会觉得“更好看”。
- 当前灵签 / 福将沿用上一轮独立彩色图谱并受统一滤色；它们与更克制的水墨背景是否完全协调，需要手机真机判断。
- 四组亮满、六签花满和结算特效同时出现时的视觉节奏，需要玩家完整打局而不是夹具截图验证。
- 若手机上觉得整体偏灰，下一轮应提高牌面、签名和主按钮局部对比，不把整套视觉退回蓝灰电子牌桌。
