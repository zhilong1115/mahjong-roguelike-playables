# 银金彩签与待缘奇缘纸面复核

日期：2026-07-26

版本：当前工作树，仅 `0015` 文档提案，尚无品阶或签兆代码

设备与视口：静态复核现有 360×800、390×844、844×390 求签布局；未制作四选一界面

测试人背景：内部设计 / 工程复核，不是真人玩法试玩

本次假设：银 / 金 / 彩签阶能增加求签期待；鸿运和广缘留下的一次性签兆能让两次求签形成组合，同时不让彩签或全亮成为固定答案。

## 观察

- 当前三选一只保存三个 `charmId`，没有签阶、签实例或跨副奇缘状态。
- 当前问签印可以重抽内容；若签阶也跟着重抽，玩家会利用重抽刷彩签，因此签阶位置必须在本次签局首次生成时锁定。
- 当前签气从对子本组池取第一张，现有池下实际固定获得双喜签，并不是真正随机；它不能直接复用未来含改命和签兆的通用池。
- 当前 `retryBlind()` 只清本关分数、待结算金币和手数。若签兆直接放在整局根状态，失败尝试取得的签兆会被带入重试，形成刷取路径。
- 四选一的 DOM 循环本身不困难，主要成本在求签快照、一次性消费、失败回滚、schema v4 迁移与窄屏布局。
- 已验证的 360×800 三签裁切会在四选一时更严重；四张签不能继续放在 `#table` 内。

## 纸面参数

- 普通签阶版式暂测：72% 银 / 银 / 银，25% 银 / 银 / 金，3% 银 / 银 / 彩。
- 同一签局最多一张金签或彩签；签兆产生的第四张首版固定为银签。
- 亮满六次时至少见到一次彩签的纸面概率约 16.7%；这不是试玩结论。
- 首批签兆：鸿运签保证下次至少一张金签并有 15% 升彩；广缘签让下次四选一但仍只取一张。

## 结论

- 保留：职责和签阶分开；卡面同时写`助势 / 改命 / 奇缘`与`银 / 金 / 彩`。
- 保留：只有一个待缘位，新签兆替换旧签兆需要确认，不堆叠队列。
- 保留：签兆在下一次新求签成功生成时消费；问签重抽保留签数和签阶，只换内容。
- 修改：本关开始时保存待缘快照，失败重试恢复，避免失败尝试刷取或吞掉进关前签兆。
- 修改：签气首版使用专用银色即时助势池，不自动给改命、彩签或签兆。
- 修改：求签层必须移到根级，竖屏三签采用 `2+1`、四签采用 `2×2`，并补实际可见面积和 48×48 点击区断言。
- 尚不确定：72 / 25 / 3 是否合适，必须按真实亮牌次数模拟；不能用一次截图或少量 seed 当作概率结论。
- 尚不确定：签兆是否足够值得放弃当前助势 / 改命，以及彩签是否仍会成为自动选择；需最小代码切片与真人试玩。
