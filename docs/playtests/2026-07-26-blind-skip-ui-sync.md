# 跳局后选关界面不同步复核

日期：2026-07-26

性质：玩家报告后的缺陷复现与回归检查；不改变 `0013` 的玩法规则

## 问题与成功信号

玩家在庄局点击“跳局”后收到成功提示，但选关界面仍把庄局显示为当前关；再次点击旧按钮时，核心已经位于圈主，因此返回“圈主不能跳”。

修复成功需同时满足：

- 跳过闲局后，界面立即把庄局标为当前关，并把闲局标成“已跳”。
- 跳过庄局后，界面立即把圈主标为当前关，并把庄局标成“已跳”。
- 圈主当前卡不再显示“跳局”按钮，旧按钮不能继续操作新关卡。
- 跳局后的键盘焦点落到新当前关的“开打”按钮。
- 核心状态和可见界面始终指向同一关。

## 修复前复现

在 `http://127.0.0.1:4173/src/?seed=12&intro=0` 真实点击“跳局”后：

- 顶部牌桌状态已经从“东圈·闲局”变为“东圈·庄局”，证明核心指针已推进。
- 覆盖层仍显示旧闲局的“开打 / 跳局”，没有“已跳”印章。
- 原因是覆盖层为一次性构造的 DOM，而界面同步只比较 `status`；跳前跳后都是 `blind-select`，所以跳过了重建。

## 验证结果

- 修复只发生在 UI：跳局回调在核心同步发出新快照后，立即用新状态重建选关覆盖层；核心推进规则没有改动。
- 重建后焦点落到新当前关的“开打”按钮，旧“跳局”按钮从 DOM 断开。
- 在浏览器从东圈闲局连续真实点击两次“跳局”：第一次立即显示庄局并给闲局盖“已跳”，第二次立即显示圈主并给庄局盖“已跳”；圈主只保留“开打”。
- 新核心回归锁定 `闲局 → 庄局 → 圈主` 指针、两个“已跳”结果和圈主不可跳。
- 新浏览器回归同时断言核心关卡、当前卡、按钮集合、焦点和旧按钮连接状态。
- `node --test tests/src-*.test.mjs`：66 / 66 通过。
- `node --test tests/*.test.mjs`：119 / 119 通过。
- `node tests/src-viewport-smoke.mjs`：required 六视口及新增庄局跳圈主路径通过，无关键裁切、遮挡或页面滚动。
- `node --check` 与 `git diff --check`：通过。

## 结论

玩家报告成立，根因是同状态覆盖层的 UI 去重，不是跳局规则或核心指针错误。修复后可见选关状态与核心状态同步，本次不改变 `0013` 的 `Proposed` 状态。
