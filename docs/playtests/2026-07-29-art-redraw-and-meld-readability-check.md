# 2026-07-29 · 美术重绘与单牌亮组屏幕检查

状态：`Automated Layout Check`（不是玩家审美结论）

## 验证目标

1. 灵签与福将都从 Library id 稳定映射到独立图谱格，不因抽签、商店或百牌谱入口不同而换图。
2. 六个开运位在横屏一排、竖屏 3×2，选完签后能看见图案、签名和签阶。
3. 中央一组只显示一张代表牌与水墨字标；窄竖屏不能把它挤出牌桌。
4. required 六视口没有页面滚动、关键裁切、手牌溢出或不可点操作。

## 方法

- `tests/src-card-art.test.mjs` 检查 19 张灵签、11 位福将的映射唯一性，以及两张 WebP 图谱均存在、总大小低于 600 KB。
- `tests/src-viewport-smoke.mjs` 在六个 required 视口打开百牌谱、牌桌、求签、改命、商店与请将台。
- 每个视口额外建立 `meld-*` 视觉夹具：亮出一组对子、放入一张金签，断言 DOM 中恰有一张代表牌、一枚 `对` 字标和一张签面。
- 人工查看 844×390 与 360×800 的 `meld-*`、`draft-*`、`general-draft-*` 和 `library-*` 截图。

## 结果

- 规则 / Library 测试、全仓测试与 viewport smoke 均通过。
- 844×390 同屏可见六个开运位、一张大亮组、牌墙预览、14 张手牌与操作按钮。
- 第一轮 360×800 截图显示亮组被常驻信息区挤到只剩牌尖；压缩窄竖屏构筑栏与开运位后，代表牌、`对` 字和牌墙预览完整可见，触控最小高度仍为 44px。
- 灵签图谱在求签卡、顶部短签位和百牌谱使用同一图；福将在请将台与百牌谱使用同一图。

## 尚未验证

- 这次只证明布局和映射正确，不能得出“美术已经好看”或“风格已经统一”的结论。
- 四组同时亮满、水墨字连续触发时的视觉密度需要真人完整局截图。
- 生成图谱与代码绘制麻将牌是否属于同一材质世界，需要用户在真机上判断后再校色。
