# Progressive Meld Demo Playtest

日期：2026-07-25

状态：`Internal Verification Complete / First User Feedback Received`

试玩版本：`prototype/progressive-meld-demo/`

工作名：`十四福将 / Lucky Fourteen`

## 要验证的假设

玩家能通过“一张换、成组留、凑齐胡”理解并享受渐进组牌，而不需要先学习传统麻将摸打流程。

## 本次只实现

- 每副牌从 14 张未整理牌开始。
- 单张弃一摸一。
- 合法对子、顺子、刻子和杠锁入组合区。
- 未整理牌与组合区共同构成胡牌。
- 四面子一将全部锁定归位后，玩家主动点击“胡”并统一结算。
- 一个教学用固定 seed / 固定牌墙场景。
- 普通组合免费拆组、杠补牌后不可拆，方便先验证核心循环；这不是正式规则。
- 简化福将效果、待结算筹码、音效和结算反馈。

## 暂定实验参数

- 单张换牌预算：12 次。
- 对子：20 筹码。
- 顺子：30 筹码。
- 刻子：45 筹码。
- 杠：80 筹码，并补摸一张结构牌。
- 基础胡牌倍率：4。
- 试玩用特殊胡法倍率：清一色 ×2、一条龙 ×1.5、大三元 ×2.5、大四喜 ×4；多个标签暂按乘法叠加。
- 教学牌墙保证关键等待牌在早期出现。

这些参数均为 `Proposed / Experimental`，不能从本次实现推断为正式平衡。

## 操作规则

- 点击未整理牌选择；再次点击取消。
- 选择一张时，主按钮显示“换牌”。
- 选择合法 2–4 张组合时，主按钮显示对应组合名。
- 无效组合不能提交，并给出文本原因。
- 点击已锁定的对子、顺子或刻子可免费拆回未整理区；杠补牌后不可拆。
- 支持触控、鼠标和键盘焦点，不依赖悬停或右键。

## 成功信号

- 首次可操作时间不超过 3 秒。
- 玩家在 45 秒内完成第一次换牌或锁组。
- 玩家能指出锁定组合仍属于最终胡牌。
- 单步通常在 5–15 秒内完成。
- 胡牌前能感到进度积累，胡牌时有明显高潮。
- required 视口无页面级意外滚动、关键按钮裁切或不可操作。

### 用户首轮反馈

- 强制把四个面子和一个将全部锁定后才能胡，容易让游戏只剩普通四面一将流程，七对无法自然成立。
- 胡牌资格不应依赖是否把组合全部手动归位；完整结构合法时，应允许玩家直接胡。
- 主动亮牌应该是为了更高得分或抽取功能牌，而不是胡牌的强制手续。
- 完全不亮牌的直接胡需要独立回报，用户倾向于给予金币，之后在商店购买长期能力。

这轮反馈不支持把 V1 渐进锁组提案提升为正式规则。后续改测 V2：“门清拿金币、亮牌开灵签”，并加入七对路线。

### 当前结论

- **已验证**：规则在代码层自洽；不能用完整散牌绕过渐进锁组或在最后一摸成牌后误流局；三个策划牌谱可完成；基础操作、特殊胡法 Bonus、结算、resize 和视口布局工作正常。
- **尚未验证**：陌生玩家是否能在 45 秒内理解；免费拆组是否削弱决策；12 次换牌是否合适；随机局的胡牌率；是否有“再来一副”的欲望。
- **下一实验**：由用户先试玩顺水局、杠上局和迷局，记录最想继续与最困惑的各一个瞬间，再决定是否保留渐进锁组。
