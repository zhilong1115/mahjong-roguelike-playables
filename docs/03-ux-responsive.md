# UX and Responsive Strategy

状态：`Accepted Direction / Layout Pending`

## 平台事实

YouTube Playables 要求游戏适配各种比例、响应视口变化并且不能锁定设备方向。因此“横屏还是竖屏”是主界面优先级选择，不是禁止另一个方向。

## 已接受的方向策略

采用 **横屏优先、竖屏完整支持**：

- 横屏是主要体验和视觉基准，按最多 14 张麻将牌、构筑栏、计分反馈和主要操作同时清晰可见设计。
- 竖屏不是简单把横屏画面缩小，而是切换成紧凑的信息层级和面板。
- 不锁定方向；玩家旋转设备或平台改变视口时，当前摸牌、选择、计分和商店状态保持不变。

决定记录在 `decisions/0002-orientation-strategy.md`。

## 横屏信息层级建议

```text
左侧：目标、当前分数、剩余摸打/弃牌、资金
顶部：福神牌、消耗品和槽位
中部：牌桌、当前组合与计分触发
底部：最多 14 张手牌
右下：主要操作与牌库信息
抽屉：番种表、完整牌库和设置
```

## 竖屏兼容层级建议

```text
顶部：目标、当前分数、剩余出牌
中部：福神牌横向栏 / 当前计分反馈
主区：最多 14 张紧凑手牌，可分层、扇形或两行排列，但不能依赖横向页面滚动
底部：出牌、弃牌、排序
抽屉：牌库、番种表、详细状态
```

商店和卡牌详情使用全屏面板，不在狭窄主界面同时展示全部信息。

## V2 垂直切片映射

- 顶栏同时显示整局福将、本副灵签和紧凑进度；灵签在亮牌前显示下一张预览。
- 牌桌上方只保留两个亮牌位，中央留给成牌与触发反馈，14 张手牌始终是最大交互对象。
- 桌面 1280×720 使用右侧状态机台；844×390 及较窄视口把目标、分数和金币压入顶栏，不让右栏挤压手牌。
- 手机和平板竖屏把 14 张手牌改为 7×2，并把主要操作固定成两层操作台；不依赖横向滚动。
- 百宝阁使用全屏弹层，三件福将同屏三选一，不做刷新和出售。

`tests/v2-viewport-smoke.mjs` 已覆盖 required 六视口、商店横竖屏、48×48 触控目标、裁切、页面滚动、手牌溢出与 resize 状态保持。该结果只证明布局可操作，不替代真人可读性试玩。

## 交互规则

- 选择牌：单击/单触。
- 卡牌详情：点击打开详情面板。
- 使用/出售：详情面板中的明确按钮。
- 取消：再次点击、取消按钮或键盘 Esc。
- 不将长按作为唯一操作。
- 不将颜色作为唯一状态提示。

## `0014` 改命灵签交互提案

状态：`Proposed`，金色单牌改命切片正在实现

改命签比现有被动加分签多一个选目标步骤，必须留在同一牌桌上下文完成：

```text
三签选一 → 选择带“成胡 / 升胡”标签的签
→ 界面重画当前未亮手牌，只让有合法结果的牌可点
→ 选择原牌后，下方只显示会减少成胡距离的目标牌种，并预览“还差 2→1”
→ 点击目标牌种即确认提交；返回按钮回到选原牌，取消按钮返回原三签
```

- 现有求签已经是根级全屏决策层；横竖屏都在同一层重画未亮手牌与目标牌网格，不依赖被遮住的底层牌桌。
- 不使用拖拽或悬停。合法牌、花色按钮和确认按钮都以 48×48 CSS px 为目标。
- 颜色之外必须显示 `加分 / 成胡 / 升胡 / 返金` 文字标签。
- 旋转、后台恢复或读档时保留三签、已选灵签、合法目标和预览状态。
- 普通三选一平均仍以 5 秒为目标；带目标的完整改命流程以 8 秒为首轮目标。
- 2026-07-26 截图复核确认现有 `#draftLayer` 在 360×800 被牌桌高度裁切。实现目标模式时，窄竖屏的签层必须跨出当前牌桌高度，且 viewport smoke 要直接检查标题、三张签和确认按钮的可见面积。

具体规则和候选卡见 `decisions/0014-charm-momentum-and-fate.md`。

## `0015` 签阶与待缘位提案

状态：`Proposed`，最小签阶 / 待缘与金色单牌改命目标界面已实现

- 每张卡同时显示 `[银签 / 金签 / 彩签]` 与 `[助势 / 改命 / 奇缘]`。签阶还要使用 1 / 2 / 3 枚签纹、不同边框层数和签头轮廓，不能只靠颜色或闪光。
- HUD 增加单格`待缘位`，横屏显示名称与触发条件，竖屏压成`待缘｜下次求签`单行；点击可看详情，不混入六个开运位。
- 待缘位已有签兆时选择新签兆，在原决策层比较“当前 / 新签”，只提供`返回选签 / 换成新缘`，不能静默覆盖。
- 鸿运或广缘应验时，标题显示`签兆已应验`；效果写入当前签局后待缘位清空，不再弹第二层说明。
- 844×390 的三签 / 四签横排；360×800 与 390×844 的三签用 `2+1`、四签用 `2×2`，不分页、不横向滚动。
- 求签层统一移到 `#app` 根级固定决策层，避免现有 `#table` 的 `overflow:hidden` 继续裁切窄竖屏。
- 普通三选一平均目标不超过 5 秒，四选一不超过 6 秒，包含待缘替换确认不超过 8 秒。
- 自动化除 viewport 边界外还要检查所有 overflow 祖先的实际可见交集、遮挡、48×48 点击区、灰度辨识和 `1–4 / Esc` 键盘路径。

2026-07-27 的金色改命切片在同一根级求签层重画 14 张未亮手牌与合法目标牌网格；Esc 可从目标返回原牌、再返回三签，选择中途可存档恢复。required 六视口已经覆盖两步交互。借张、整组改花色等其他 `0014` 交互仍未实现，不能据此宣称完整灵签方案已经验证。

完整规则见 `decisions/0015-charm-tiers-and-pending-omens.md`。

## 尺寸与安全区

- 目标触控区：至少 48×48 CSS px。
- 关键按钮之间保留至少 8px 间隔。
- 尊重 `safe-area-inset-*`，避免被刘海、圆角和平台控制遮挡。
- 不出现页面级横向滚动。
- 视口变为 0×0 或重新变大时不得崩溃或重置状态。

## `0024` 开运位与亮组表现

状态：`Accepted`，首轮实现完成，等待手机审美试玩

- 开运位仍为六格：横屏一排，竖屏 3×2；已取得的灵签以“图案 + 签名 + 签阶”的短签牌显示，不再压成超宽文字条。
- 牌桌中央每个已亮组合只显示一张代表牌；对子 / 碰 / 杠取同牌，顺子取中张，上方用水墨字标 `对 / 碰 / 杠 / 顺`。
- 四组亮满时让亮组成为牌桌主体，但不能遮住牌墙预览、手牌或主要操作。
- 360×800 在牌桌已有亮组时压缩构筑栏与六格开运位，至少给一张代表牌和墨字留出完整高度；不靠页面滚动补救。
- 视觉回归要同时检查弹层内的大卡图和选签后的 `meld-*` 场景，后者必须断言每组只有一个 Canvas 牌面。

具体美术与数据映射见 `decisions/0024-art-redraw-and-compressed-melds.md`。

## `0025` 古典水墨统一与大开运位

状态：`Accepted`，首轮实现完成，等待手机审美试玩

- 标题页与牌桌统一使用本地原创水墨背景：宣纸、淡墨远山、旧木、温玉和朱砂成为主材质；不依赖网络字体或图片。
- Logo 改成代码绘制的墨圈、`天胡` 行楷与朱砂方印；系统字体只承担正文和小字号信息。
- 麻将牌继续用确定性 Canvas 绘制，但牌面改成旧象牙 / 宣纸釉，牌背改成乌木 / 旧漆上的山、云、回纹和北斗纹样。
- 开运位主动占用更多牌桌面积：1280×720 与 960×960 的牌架实测 132px 高、844×390 为 88px；360×800 的 3×2 单格为 56px、较宽竖屏为 64px。
- 扩大开运位不能缩小 14 张手牌或主要操作；中央亮组继续使用一张代表牌，所以四组亮满时仍有可辨识空间。
- viewport smoke 直接读取 `slotBarHeight` 和最小开运位高度，避免后续 CSS 调整把它悄悄压回细条。

具体视觉决定见 `decisions/0025-classical-ink-art-direction.md`。

`0027` 根据真机反馈只在矮横屏把牌架重新压到约 68px；桌面、方屏和竖屏仍沿用本节的大开运位层级。

## `0027` 横屏全宽手牌与紧凑状态分组

状态：`Accepted`，首轮实现完成，等待手机真机确认

- 横屏骨架改成两层：上层左侧是状态、右侧是构筑带与牌桌；底部 `#handDock` 横跨整屏，左栏不能再占用手牌宽度。
- 14 张手牌在 667×375 与 844×390 都必须单排；牌面大小按 `#handZone` 的真实宽度计算，不按右侧牌桌宽度猜测。
- 左栏只保留四组里前三组：关卡进度、当前牌势、本副资源；本局构筑移到牌桌上方的横向带。
- 从左栏删除重复的成胡距离和空位收益：前者由操作提示 / 胡牌按钮表达，后者由六个开运位本身表达。
- 福将继续显示有限将位；番谱 / 牌骨 / 牌印 / 牌帖继续是可点摘要。辅助操作在构筑带右端单独成组。
- 矮横屏开运位压到 58px 单格、操作按钮保持至少 44px；节省空间不能以缩小手牌点击区为代价。
- viewport smoke 除 required 六视口外新增 667×375，直接断言横屏手牌只有一排、手牌区宽于牌桌区、左栏在手牌上方结束。

具体审计与取舍见 `decisions/0027-full-width-hand-and-compact-hud.md`。
