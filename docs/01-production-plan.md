# Production Plan

## 阶段与门槛

### P0 — 项目定义

产物：愿景、平台范围、屏幕策略、成功指标。

完成条件：关键产品问题有 decision record，不依赖口头记忆。

### P1 — 玩法预制作

产物：核心循环、单局流程、资源经济、番种体系、构筑体系、教学流程。

完成条件：可以用纸面或原型完整解释一局，主要规则没有互相矛盾。

### P2 — 垂直切片

产物：一套接近最终品质的可玩短局，包含开始、教学、构筑、Boss、结束和续玩。

完成条件：陌生玩家无需口头指导完成第一局；required 视口可玩。

玩法门槛：垂直切片通过后冻结核心循环，大改必须新建 decision record。

### P3 — 正式生产

产物：完整内容、原创视觉、音频、存档、平台适配、自动测试。

完成条件：所有计划功能进入游戏，不再依赖临时代码和占位资源。

### P4 — Alpha

产物：功能完整版本。

完成条件：从首次启动到胜利、失败、恢复存档都能完整运行。

玩法门槛：停止增加大型系统，只允许平衡、内容、教学和可用性调整。

### P5 — Beta / Certification Candidate

产物：发布候选包、平台元数据、缩略图、测试报告、权利清单。

完成条件：内容锁定；只修 Bug、兼容性、性能和认证问题。

### P6 — Release / Updates

产物：正式发布和版本更新流程。

完成条件：每个平台拥有可重复构建、测试、上传和回滚步骤。

## 工作流

每一个较大的功能按以下循环推进：

```text
问题/机会 → 设计假设 → 最小实现 → 试玩 → 数据和反馈 → 接受/修改/删除
```

## 玩法状态词

- `Idea`：仅记录，尚未评估。
- `Proposed`：有具体方案，等待决定或测试。
- `Accepted`：当前版本按此执行。
- `Frozen`：除非有明确证据，否则不再改变。
- `Rejected`：保留原因，避免以后重复讨论。
